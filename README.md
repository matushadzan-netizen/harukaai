# HarukaAI — офлайн Android-чат с распознаванием изображений

Проект собирает Android APK. После установки приложение не обращается к сети: в `AndroidManifest.xml` намеренно отсутствует разрешение `INTERNET`, а инференс выполняется локально через `llama.cpp`.

## Сборка APK через GitHub Actions

1. Создай пустой репозиторий на GitHub.
2. Распакуй содержимое этой папки `HarukaAI` и загрузи все файлы в репозиторий (включая скрытую папку `.github`).
3. Открой вкладку **Actions** и разреши запуск GitHub Actions, если GitHub попросит.
4. Выбери workflow **Build HarukaAI offline APK** → **Run workflow**.
5. После успешной сборки открой запуск workflow и скачай артефакт **HarukaAI-debug-apk**. Внутри будет `HarukaAI-debug.apk`.

Workflow автоматически загружает исходники `llama.cpp` (закреплённая версия с legacy LLaVA API), устанавливает Android NDK/CMake и собирает APK. Сеть нужна только компьютеру/CI во время сборки, не самому приложению при работе.

## Как включить распознавание изображений

Нужны **две совместимые GGUF-модели** от одного и того же релиза:

- основная vision-модель LLaVA в формате `.gguf`;
- соответствующий ей файл проектора `mmproj-*.gguf`.

В приложении нажми **Pick .gguf model**, выбери основную модель, затем **Pick mmproj**, выбери проектор и нажми **Load model**. После загрузки нажми кнопку камеры, выбери изображение, напиши вопрос и отправь.

Важно: обычная текстовая GGUF-модель не умеет распознавать картинки. Для изображений обязательны vision-модель и её парный mmproj. Размер модели должен помещаться в оперативную память телефона; для LLaVA 7B обычно требуется много свободной RAM (ориентировочно 6–8 ГБ и более). Для слабых устройств нужна специально облегчённая vision-модель, совместимая с тем же мультимодальным интерфейсом.

## Название приложения

Название приложения — **HarukaAI**. Интерфейс без декоративных бабочек и фоновой анимации.

## Полностью офлайн

- В манифесте нет `android.permission.INTERNET`.
- Модели выбираются из локальных файлов телефона.
- После установки и копирования моделей можно включить авиарежим: генерация текста и обработка изображений выполняются на устройстве.
- Скачивание APK и моделей — отдельный предварительный шаг, для него интернет понадобится.

## Технические параметры

- Android 8.0+ (minSdk 26)
- `arm64-v8a` и `x86_64`
- Android NDK 26.3, CMake 3.22.1, Java 17
- CPU-сборка как наиболее совместимый базовый вариант

## Ограничения текущей версии

Это исходный проект и автоматизированный рецепт сборки, а не проверенный на конкретной модели телефона релиз. Перед распространением нужно проверить успешный запуск на целевом устройстве и выбранной паре LLaVA/mmproj: поддержка форматов мультимодальных GGUF зависит от версии `llama.cpp` и конкретной модели. Если GitHub Actions завершится ошибкой, открой лог шага **Compile APK** — по нему можно точечно исправить несовместимость API/NDK.

## Ролевая функция

В приложении есть отдельная вкладка **«Ролка»**. В ней можно создавать, редактировать и удалять персонажей. Поля карточки: имя, пол, краткое описание, внешность, характер, предыстория, отношение к собеседнику, манера речи, привычки, теги, первая реплика и вводная сцена. Карточки сохраняются локально в SharedPreferences. Доступен импорт JSON-карточек с распространёнными полями `name`, `description`, `personality`, `first_mes` и `scenario` (в том числе с вложенным объектом `data`). При запуске ролевой сессии описание персонажа добавляется к запросу локальной языковой модели.

## Huihui AI / Dolphin 3

Встроенный движок приложения — `llama.cpp`, который загружает локальные GGUF-файлы. Команда `ollama run huihui_ai/dolphin3-abliterated` предназначена для запуска модели через Ollama на компьютере/сервере; Android-приложение не содержит Ollama и не может выполнить эту команду напрямую. Чтобы использовать эту модель в HarukaAI офлайн, нужна совместимая с `llama.cpp` GGUF-сборка этой модели (если доступна), подходящая по размеру для RAM телефона. Её можно выбрать обычной кнопкой **«Выбрать GGUF»**. Поведение модели определяется её обучением; приложение не обещает отсутствие любых ограничений.

## Генерация изображений — ограничение

Текущая нативная связка `llama.cpp` поддерживает текстовую генерацию и, при наличии совместимой vision-модели с `mmproj`, анализ входных изображений. Она **не генерирует новые изображения**. Для настоящей офлайн-генерации картинок требуется отдельный diffusion-движок (например, Stable Diffusion) и совместимые модели весом в несколько гигабайт, а также отдельная JNI/Android-интеграция. Эта функция в данном архиве пока не реализована; кнопка или экран, имитирующие готовую генерацию, намеренно не добавлены.
